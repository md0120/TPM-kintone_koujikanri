# フィールド対応表

各アプリのカスタムJSが実際に参照しているフィールドを一覧化したもの。kintoneでは
「表示ラベル」と「フィールドコード（API上の識別子）」が一致しないことが多く
（フィールド作成時に自動採番されたコードがそのまま残っている等）、これが原因の
不具合を複数回踏んでいる（例：「年度」は実は`数値`、「ルックアップ」という名前
なのに実体は1行テキスト、など）。フィールドを操作するスクリプトを書く・直す前に、
このページで実際のフィールドコードを確認すること。

全フィールドを網羅した表ではなく、**カスタムJSから参照されているフィールドのみ**
掲載している（使われていない項目までここに含めると情報過多になり、かえって
見づらくなるため）。全フィールド一覧が必要な場合は`GET /k/v1/app/form/fields.json`
で都度確認する。

## 命名の癖（覚えておくと調査が早い）

- **フィールドコードが自動採番のまま残っている**ことが多い（`文字列__1行_`、`ドロップダウン_3`、`日付_5`など）。表示ラベルだけを見て「同じ名前だから同じフィールドだろう」と判断しない。**app が違えば同じコードでも中身は無関係**（例：app37とapp43はどちらも`文字列__1行_`というコードを持つが、app37では「工事名」、app43では「app37レコード番号」という全く別の用途）。
- **「〜ドロップダウン」という表示上の見た目でも、実際の型はDROP_DOWNとは限らない**（TPM担当・着打ち(顧客)はSINGLE_LINE_TEXT）。in演算子や選択肢の取得方法が型によって変わるため、触る前に`GET /k/v1/app/form/fields.json`で`type`を確認する。
- **フィールド名を変更・リネームする際は、参照している全スクリプト・他アプリのREFERENCE_TABLE設定を洗い出してから行う**（2026-09-20の`ルックアップ`→`工事名テキスト`リネームでは、app38・app40の当該フィールドに加え、app37の関連レコード一覧2件のrelatedField設定、shared配下3ファイル、app38の進捗連携.js・_mobile.jsの計7箇所を同時に更新する必要があった）。
